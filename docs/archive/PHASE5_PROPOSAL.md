## 2. История выполнения Claude Code (приоритет 1)

### 2.1 Документировано

- **PostToolUse:** `tool_name`, `tool_input`, `tool_response`, `tool_use_id`, `duration_ms`. Для Bash в `tool_response` есть `stdout`, `stderr`, `interrupted` и `isImage`; кода выхода нет.
- **PostToolUseFailure:** `error` (для Bash первая строка `Exit code N`), `is_interrupt`, `duration_ms`.
- Внутри субагентов приходят `agent_id` и `agent_type`.
- Вызовы можно сужать через `matcher` и `if`. Есть режим `async`.

### 2.2 Выбор

Используем хуки. Транскрипт не читаем.

### 2.3 Проверка в песочнице до изменения плагина (этап 5.1)

Только `claude --settings <file>` или `settings.local.json` песочницы с
отдельным data dir. Плагин и `~/.claude/settings.json` не трогаются.

### 2.4 Минимальная запись `tool_event`

Хранятся только:
- общие поля: `tool_use_id`, `session_id`, `prompt_id`, `agent_id`, `agent_type`, `received_at`, `duration_ms`, `outcome`;
- для Bash: `exit_code` (только из `Exit code N`), `command` (не больше 1 KB и без подозрения на секрет, иначе `withheld`), `kind` (`test`, `build`, `git` или `other`), `background`, `output_tail` (только у упавших `test` и `build`: 12 строк, не больше 2 KB, после проверки на секреты);
- для Write, Edit, MultiEdit и NotebookEdit: `path`;
- для SendUserFile (если подтвердит V4): `paths`;
- для Artifact (если подтвердит V9): `source_path`, `url`, `title`, `version`, `audience`.

Не хранятся никогда:
- stdout и stderr успешных команд;
- содержимое файлов, `old_string`/`new_string`, `tool_response` у Write и Edit;
- HTML артефакта.

«exit 0» не означает успех задачи. Это код одной команды, а при пайпе — код последнего процесса.

### 2.5 Привязка

- Сессия — по `session_id`, ход — по `prompt_id`.
- Без `prompt_id` событие привязывается к ходу, только если в сессии ровно один незавершённый ход. Иначе оно получает метку `unlinked` и показывается только счётчиком.
- Субагенты идут отдельной группой.
- События, пришедшие после Stop, помечаются.
- `/compact` ничего не меняет.

## 3. R10: единые вложения (Attachments)

### 3.1 Типы

| Тип (`kind`) | Что это | Где показывается | Что уходит в ChatGPT |
|---|---|---|---|
| `document` | Markdown, TXT, JSON, CSV, YAML, исходный код (UTF-8, ≤ 1 MB) | карточка: имя, формат, размер, строки | файл; для небольших документов по выбору — текст внутри пакета |
| `pdf` | PDF и другие документы с постраничным просмотром | карточка: миниатюра первой страницы (PDFKit), число страниц | файл |
| `image` | PNG, JPEG, HEIC, TIFF, скриншоты | миниатюра 96 px | файл (PNG/JPEG) |
| `link` | внешний URL | хост, заголовок только если известен из события; **страница не загружается** | только URL и его доступность («private Claude link — recipient likely cannot open») |
| `mockup` | интерактивный макет или визуальный артефакт (§4) | карточка макета: название, источник, число состояний, сколько сохранено | снимки состояний под структурированными именами и описание каждого |

### 3.2 Модель данных (расширение `ReportAttachment`, без нового хранилища)

Новые поля в существующем индексе `attachments.json`:
- `kind`: `document`, `pdf`, `image`, `link` или `mockup`; у старых записей по умолчанию `image`;
- `source`: `you`, `claude_tool` (с `tool_use_id`), `clipboard`, `response_link` или `artifact_tool`;
- `availability`:
  - `stored` — есть копия;
  - `missing` — оригинал исчез до копирования;
  - `link_only` — есть только ссылка;
  - `failed` — с причиной;
- `capturedAt` и `originalPath` (только для показа; в пакет попадает путь относительно проекта или только имя);
- `selected` (выбрано для экспорта) и `order`;
- `inlineText` — только для небольших документов, по выбору пользователя.

У `mockup` есть дочерние записи `mockup_state`: `stateID`, `title`,
`description`, `order`, `status` (`captured`, `named_only` или `failed`),
ссылка на сохранённое изображение, `capturedAt`, `method` (`manual_import`,
`local_render` или `clipboard`) и `interactiveNotes` (например, «gaze slider,
copy toggle»).

Копия файла (`stored`) — это **снимок на момент прикрепления**: SHA-256,
время, права 0600. Если оригинал потом изменился, карточка пишет «changed
since attached» и предлагает обновить снимок, но сама ничего не обновляет.

### 3.3 Откуда берутся кандидаты (не каждый изменённый файл)

1. **Пользователь:** 📎 Add, перетаскивание, вставка (как сейчас, плюс новые типы).
2. **Claude явно показал пользователю:** SendUserFile (V4) и Artifact (V9). Такие материалы предлагаются **выбранными**.
3. **Claude создал файл и назвал его в ответе:** путь из Write или Edit этого хода, который встречается в тексте финального ответа (ссылка `[…](path)` или путь в обратных кавычках). Такие файлы предлагаются, но **не выбраны**.
4. **Остальные изменённые файлы** — только в разделе «Files Claude changed» как пути, без вложений.
5. **Ссылки** из финального ответа: показываются списком, не выбраны и не загружаются.

Проверки при копировании (как для изображений, §3 ред. 2):
- `realpath` внутри папки проекта, `scratchpad_dir`, `$TMPDIR` или `/tmp`; без симлинков наружу;
- тип определяется по содержимому (UTType и ImageIO, PDFKit, валидный UTF-8);
- лимиты: документ ≤ 1 MB, PDF ≤ 50 MB, изображение ≤ 20 MB;
- проверка на секреты для текстовых документов: при находке появляется предупреждение и вложение не выбирается.

### 3.4 Quick Peek и Details

- **Quick Peek:** одна строка-итог «1 document · 1 mockup (7 states, 7 saved) · 2 images» и чип «Visual review required», если выбран макет. Списков в Quick Peek нет.
- **Details:** область Attachments. Отдельный вид «All attachments» с группами Documents, Mockups, Images, Links. В каждой карточке: имя, формат, размер, источник, доступность, галочка выбора, ×, ⋯ (Open, Show in Finder, Update snapshot). Прокрутка внутри области.

## 4. R11: интерактивные макеты и Claude Artifacts

### 4.1 Что такое «состояние»

Это именованный экран макета: Resting, Quick Peek, Details и так далее. У
каждого свой `stateID`, название, краткое описание и материал. Статусы:
- **`captured`** — изображение реально сохранено в Prompt Relay (есть SHA-256 и время);
- **`named_only`** — известно только название (из объявления состояний в источнике или введено пользователем); изображения нет;
- **`failed`** — попытка снять состояние не удалась, причина записана.

Найденная ссылка никогда не считается прочитанным или экспортированным
артефактом.

### 4.2 Пометка

Каждый макет в UX и в пакете несёт пометку **«Visual mockup — review
required»** («Визуальный макет — требуется просмотр»). В пакете под ней
стоит строка: «ChatGPT can review the attached state images. Transitions,
animations, pointer reactions and feel cannot be judged from still images;
the owner reviews them separately.» У каждого состояния с интерактивными
элементами перечислено, что на снимке не видно (ползунки, переключатели,
анимации).

### 4.3 Что доступно: автоматически, явным экспортом, недоступно

| Данные | Как | Статус |
|---|---|---|
| Что Claude вызвал Artifact и что вернул инструмент (`title`, `url`, `version`, `audience`, путь к исходнику) | PostToolUse | **Автоматически, если V9 подтвердит.** До проверки — нет |
| Путь к исходному HTML артефакта на этом Mac (например, scratchpad) | из того же события | Автоматически, но только путь (хук файлы не читает) |
| Содержимое исходного HTML | приложение копирует файл по пути из события после явного действия пользователя «Add mockup source», с проверками §3.3 | **Только явным действием** |
| Список состояний | (а) объявлен в исходнике по соглашению §4.4; (б) введён пользователем; (в) вкладки самого артефакта Prompt Relay не угадывает | (а) и (б) явно; (в) недоступно |
| Изображение состояния | (а) ручной импорт PNG (📎, перетаскивание, буфер); (б) локальный рендер исходника в изолированном WKWebView по `#stateID` (§4.5) | (а) всегда; (б) только явно и только при объявленных состояниях |
| Опубликованная страница на claude.ai (`/artifact/…`) | нужна авторизация владельца | **Недоступно.** Не загружаем и авторизацию не обходим. Ссылка показывается с пометкой «private — recipient cannot open» |
| Документированный API экспорта артефактов для сторонних приложений | не найден | **Недоступно** (на 2026-10-30); вернуться, если Anthropic задокументирует |
| Визуальные элементы Claude Desktop без исходника (show_widget, превью браузера) | только факт вызова инструмента, если хук сработает | Содержимое **недоступно** |
| Переходы, анимации, реакция на курсор, ощущения | — | **Недоступно для автоматической проверки**; проверяет владелец |

### 4.4 Соглашение «Mockup States» (наше, необязательное)

Работает для макетов, которые **пишет Claude по просьбе пользователя**, в
том числе для макетов самого Prompt Relay. Страница объявляет свои
состояния:

```html
<script type="application/json" id="prompt-relay-states">
{"version":1,"title":"Prompt Relay Phase 5 Island","states":[
 {"id":"resting","title":"Resting","description":"…","interactive":["gaze slider","copy toggle"]},
 {"id":"quick-peek","title":"Quick Peek","description":"…"}]}
</script>
```

и открывает каждое из них по `#id` (контракт Claude Artifacts передаёт
простой `#anchor` в `location.hash`). Это **не** формат Anthropic, а
наше соглашение. Если его нет, состояния вводятся вручную. Макет в
эскизах версии 3 этому соглашению следует.

### 4.5 Локальный рендер состояний (этап 5.10, только если подтвердится)

Это вариант для макетов, у которых **есть локальный исходник и объявлены
состояния**. Запускается только кнопкой «Capture N states from source» с
диалогом, где перечислено, что произойдёт.
- **Изоляция WKWebView:** offscreen, `WKWebsiteDataStore.nonPersistent()`, JavaScript включён (без него состояния не переключаются), без доступа к файлам вне папки исходника.
- **Сеть:** весь сетевой доступ заблокирован через `WKContentRuleList`. Шрифты с CDN не загрузятся, поэтому снимок помечается «rendered locally, web fonts blocked; may differ from the published artifact».
- **Снятие:** по одному `#stateID` за раз, `takeSnapshot` с фиксированной шириной (1120 pt) и тайм-аутом 5 с. Неудачное состояние получает статус `failed` с причиной.
- **Поведение страницы:** никакой навигации, всплывающих окон и загрузок.
- **Безопасность:** код страницы выполняется на Mac пользователя, поэтому нужны отдельный ADR-016 и согласие. До этапа 5.10 этого механизма нет.

### 4.6 Имена файлов при передаче

`<project>-<artifact-slug>-<NN>-<state-id>.png`, например
`phase5-island-01-resting.png`, `phase5-island-02-quick-peek.png`.
- Порядок задаётся номером, потому что порядок вставки нескольких файлов в ChatGPT не проверен.
- Документы сохраняют исходное имя, например `PHASE5_PROPOSAL.md`.
- Копии с этими именами создаются в существующем `app/handoff/` и пересоздаются при каждом использовании.

## 5. Copy for ChatGPT

### 5.1 Разделы (ответ ровно один раз)

1. Заголовок, время экспорта, «No AI service was used», метки.
2. **Task.**
3. **Claude's final response** — дословно.
4. **Observed during this turn** — команды, `exit N`, длительность; хвосты упавших запусков; фоновые команды; субагенты.
5. **Files Claude changed** — только пути.
6. **Git state** — время сбора.
7. **Attachments, sent separately** — по группам:
   - Documents: имя, формат, размер, источник, «snapshot at HH:MM»; для небольших документов по выбору — текст внутри пакета в ограде;
   - Images: имя, размер, источник;
   - Interactive mockups: название; источник; ссылка с отметкой доступности; пометка «Visual mockup — review required»; таблица состояний (№, имя файла, название, описание, статус, способ снятия, что не видно на снимке);
   - Links: URL и доступность;
   - **Not available**: каждое `named_only`, `failed` или `missing` с причиной.
8. **Not checked** — Claude's claims; CI [Unavailable].
9. **Request** — анализ по задаче, ответу, наблюдениям, документам и снимкам; отдельно указано, что нельзя оценить по статичным снимкам.

Строка в начале раздела 7: «N files are listed here. They are part of this
review only if they are attached to this message.» Prompt Relay никогда не
пишет, что файлы переданы.

### 5.2 Передача (по умолчанию в два шага)

1. **Шаг 1:** Copy for ChatGPT → текст в буфере, проверен чтением → ⌘V.
2. **Шаг 2:** «Copy 9 files» (file URL с именами из §4.6), «Drag all 9» или «Show in Finder» (файлы выделены по порядку).
   - Если выбрано больше 10 файлов, показывается предупреждение: «ChatGPT may limit files per message — not verified».

## 7. UX островка

### 7.1 Relay в Resting (R8, окончательно, ред. 3.1)

Редакция 3 по ошибке отключала движение головы в Resting. Исправлено:
рисунок прежний (круглый Relay, 28 pt), голова и лицо анимированы и в
закрытой чёлке, пока Relay виден.

**Изучение Coucou** (<https://github.com/Louis-CFM/coucou>, коммит `37e457d`,
только чтение, клон в scratchpad):
- Код под MIT. По `LICENSE-ASSETS.md` имена «Coucou» и «Mochi», персонаж Mochi («design, look, expressions and animations as a character»), иконки, звуки и медиа не входят в MIT.
- Поэтому ничего не переносим: ни кода, ни ассетов, ни звуков, ни конкретных кривых и таймингов Mochi.
- Берём только общие приёмы, известные и без Coucou:
  - мягкое насыщение смещения курсора (tanh);
  - раздельные пружины для глаз и головы (голова отстаёт от взгляда);
  - сглаживание к цели с инерцией;
  - случайный интервал моргания;
  - короткие «пружинные» реакции.
- У Mochi `TimelineView(.animation)` рисует кадры на частоте дисплея, пока персонаж виден (`MochiFrameClock`). **Это не переносим:** Relay рисует кадры только пока что-то движется, не больше 30 fps, затем останавливается (§7.1.4).

**7.1.1 Геометрия (расчёт по контуру `NotchShape` и пропорциям `Mascot.swift`):**
- Видимый левый край уха проходит по x = 6 pt, корпус камеры начинается с x = 38 pt, верх экрана y = 0, низ уха y = 32.
- Запас в нейтральной позе (pt, слева / справа / сверху / снизу):

  | Позиция | Слева | Справа | Сверху | Снизу |
  |---|---|---|---|---|
  | сейчас, x = 5 | 0,4 | 6,4 | 2,84 | 3,96 |
  | x = 7 (+2) | 2,4 | 4,4 | 2,84 | 3,96 |
  | **x = 8 (+3)** | **3,4** | **3,4** | 2,84 | 3,96 |

- **Начальное значение: x = 8 pt (+3 pt).** Запасы симметричны, поэтому голова может одинаково двигаться в обе стороны. Окончательное значение подтверждают рендер-тесты и проверка на экране (5.4).

**7.1.2 Бюджет движения головы в Resting (при x = 8):**

| Движение | Предел | Худший запас |
|---|---|---|
| Сдвиг к курсору по горизонтали | ±1,4 pt | вместе с поворотом: 1,32 pt до края / камеры |
| Поворот вокруг центра головы (не от низа) | ±4° | верх уха 2,27 pt |
| Взгляд вверх / вниз (сдвиг головы) | −0,8 / +1,0 pt | сверху 2,04, снизу 2,96 |
| Дыхание: scaleY от низа | ≤ 1,015, период ≈ 4,5 с | вместе с «вверх-влево» сверху 1,09 |
| Радость при копировании: голова возвращается в центр за 0,15 с, затем подскок | подъём ≤ 1,5 pt | сверху 1,34 |
| Новый ответ (уши подняты на 0,7 pt) + взгляд вверх | — | сверху 1,34 |

- Глаза и мордочка смещаются внутри лица как сейчас (глаза ±0,055 s, мордочка ±0,025 s). Это добавляет ощущение поворота, не меняя силуэт.
- В открытой полосе Details места больше, бюджет там прежний (наклон 6°).

**7.1.3 Адаптивное ограничение (вместо отключения):**
- Перед каждым кадром позы вычисляются точки силуэта: два уха и голова, по 36 точек.
- Безопасная область: x ≥ 7, x ≤ 37, y ≥ 1, y ≤ 31 (1 pt от видимого края, корпуса камеры и верха экрана).
- Если поза выходит за область, коэффициент k ∈ [0, 1] для сдвига, поворота и подъёма уменьшается двоичным поиском, 8 шагов.
  - Дыхание и выражение лица не ограничиваются.
  - Голова не замирает: в худшем расчётном случае (диагональ вверх, уши подняты, пик дыхания) k ≈ 0,54: голова движется на 54 % бюджета. Проверено расчётом в Node по той же геометрии, что в эскизе.
- Вычисление — несколько сотен умножений на кадр, и только пока идёт движение.

**7.1.4 Поведение и энергопотребление:**

| Что | Как | Нагрузка |
|---|---|---|
| Глаза следят за курсором по всему экрану | цель = tanh(Δ/260) по x, tanh(Δ/200) по y; быстрая критически демпфированная пружина (≈ 0,15 с) | кадры только при движении, ≤ 30 fps |
| Голова | та же цель, что у глаз, переведённая в бюджет §7.1.2 (цель по модулю 1 → предел); более медленная пружина с лёгким перелётом (≈ 0,35 с, ζ ≈ 0,75) — инерция, голова «догоняет» взгляд | те же кадры |
| Возврат в нейтраль | голова через 1,2 с без движения курсора, глаза через 2 с; плавно, затем кадры прекращаются | — |
| Моргание | каждые 3,5–7 с, ≈ 0,2 с | несколько кадров на моргание |
| Дыхание | анимация Core Animation на слое Relay (`CABasicAnimation`, repeat) — выполняется render server, без перерисовки SwiftUI-панели | ≈ 0 % CPU приложения (проверить, V-A3) |
| Копирование (Copy Response и Copy for ChatGPT) | голова в центр, подскок ≤ 1,5 pt, счастливые закрытые глаза ^ ^ и румянец ≈ 0,8 с, затем спокойная улыбка | ≈ 1 с кадров |
| Ошибка копирования | обеспокоенные брови, лёгкое покачивание в пределах бюджета; никогда не радостная реакция | ≈ 0,5 с |
| Скрыт, дисплей спит, открыт системный диалог | всё остановлено, включая дыхание | 0 |
| **Reduce Motion** | нет движения головы, взгляда, дыхания, подскока и моргания; выражения меняются (^ ^, румянец, брови) | 0 |

- Перерисовывается только слой Relay (свой `NSHostingView` или слой размером 28 pt), а не вся панель.
- Правило «никакой анимации SwiftUI на непрерывных значениях» из Phase 4 сохраняется: раньше пружина вызывала ≈ 23 % CPU.

**7.1.5 Автотесты (5.4):**
- Рендер позы в Resting для взгляда (±1, 0), (0, ±1), четырёх диагоналей; каждого настроения; каждого кадра реакции копирования и ошибки (выборка 60 Гц); дыхания на пике.
- Проверки:
  - ни одного непрозрачного пикселя Relay вне `NotchShape` с отступом 1 pt, в прямоугольнике корпуса камеры и выше y = 1;
  - k > 0 во всех позах (голова не отключается);
  - в позах без ограничения k = 1.
- Пружины:
  - после остановки курсора поза приходит в нейтраль за ≤ 1,2 + 0,6 с;
  - затем кадры прекращаются (счётчик кадров = 0 за 2 с простоя).
- Reduce Motion: поза одинакова во всех кадрах, выражения меняются.
- Таймер кадров не работает, когда Relay скрыт или дисплей спит.

**7.1.6 Проверяется только на реальном Mac** (статичные снимки не передают):
- плавность и «вес» головы, перелёт пружины, отсутствие дрожания при медленном курсоре;
- время и естественность возврата в нейтраль;
- заметность и деликатность дыхания;
- радость при копировании: тайминг, читаемость ^ ^ и румянца в 28 pt;
- отсутствие обрезания при реальном движении (между проверенными кадрами);
- CPU и Energy Impact:
  - в простое: 0 % CPU, дыхание на render server;
  - при непрерывном движении курсора: цель ≤ 3 %;
  - 10 минут в Activity Monitor;
- ProMotion (120 Гц) и внешний дисплей без чёлки (плавающий островок);
- включение и выключение Reduce Motion во время работы;
- соседство с Coucou в той же чёлке.
